# Аудит текста в клиенте — заготовка для дизайн-прохода

> Составлен в И-24 по указанию оператора: в приложении много содержательного
> текста — методики, оговорки, объяснения решений, — но он написан «плашмя»:
> одинаковыми серыми строками FontSize 10–12 c Opacity 0.5–0.7. Ценность текста
> теряется в монотонности. Этот файл — карта мест для дизайн-прохода;
> сами правки — следующим заходом, с дизайн-плагином.

## Сквозные наблюдения (важнее отдельных мест)

1. **Один визуальный класс на четыре разных рода текста.** Сейчас одинаково выглядят:
   *методика* («джиттер по RFC 3550»), *оговорка честности* («не равно недоступности»),
   *инструкция* («сопрягите агента в настройках») и *пояснение интерфейса*
   («колесо — масштаб»). Их надо развести визуально: у каждого рода — своя форма
   (см. предложения ниже), тогда глаз научится их различать за день работы.
2. **Предупреждения продукта уже выделены** (жёлтая полоса «измерение через
   виртуальный коммутатор», оранжевые строки HowToEnable) — этот язык работает,
   его стоит распространить, а не изобретать новый.
3. **Самый ценный жанр продукта — «почему так, а не иначе»** (потери на транзитном
   хопе, MOS без потерь, счётчик — не измерение). Ему нужна самая заметная форма:
   карточка с иконкой ⓘ или спойлер «почему так», а не подвал серым.

## По страницам

### Дашборд `/`
- **«С чего начать»** (первый запуск) — уже карточка с рамкой, хорошо; остальным
  равняться на неё.
- `JournalInfo`, `InventoryInfo` — статистика и совет склеены в одну серую строку
  («В журнале 541 прогонов… Запусти измерение…»). Число — крупно, совет — отдельно.

### Задержка `/local/tests/latency`
- `MeasurementConditions` (интерфейс · порог · методика) — строка под заголовком.
  Это *условия измерения*, они сравниваются между запусками: просятся бейджи-чипы
  (интерфейс) (порог 0.221 мс) (ICMP RFC 792), а не предложение.
- `StatusLine` («Прогон остановлен. Измеренное сохранено.») — состояние теряется
  справа от кнопки пресета. Статусу — своё место и иконка состояния.

### Анализ пути `/internet/path`
- **Блок итога** (`Verdict` + `PathLengthNote` + `RouteChanges` + `AsnHint`) — четыре
  разножанровые строки подряд: вердикт, объяснение переменной длины пути, смены
  маршрута, подсказка про базу ASN. Вердикт — крупно с маркой (✓/!), объяснения —
  свёртываемые или с иконками.
- **Подвал про MOS** («MOS на транзитных хопах считается…») — главная методическая
  оговорка экрана, ради которой строился весь разбор, — самым мелким шрифтом
  в самом низу. Кандидат №1 на карточку «почему так».
- Подсказка про DB-IP (.mmdb) — инструкция с путём, вклеенная в жёлтый блок
  вместе с вердиктом недостижимости: путь должен копироваться, инструкция —
  жить отдельно от вердикта.

### Обнаружение `/local/discovery`
- Объяснение «объём показывается до запуска, темп ограничен, сканирование
  попадает в аудит» — простыня перед кнопкой. Три пункта — три строки с иконками.
- Итог скана («Опрошено X, найдено Y, MAC у Z») — числа в строке; просятся
  плитки-счётчики как внизу Задержки.

### Устройства `/local/devices`
- Подвал («Приглушённая строка — … Пометка ✎ — …») — две легенды в одном
  предложении. Легенда — отдельными парами «знак → значение».
- `StatusLine` после правки («Правка переживёт пересканирование…») — важное
  подтверждение механики, мелькает серым в шапке.

### Карта сети `/local/topology`
- Панель «Выбранный узел» — свойства идут голым столбиком без подписей полей
  (что адрес, что MAC — догадывайся по форме). Пары «подпись: значение».
- Строка «Выведенных связей N из M… Каждая названа причиной» — под картой
  простынёй; это объяснение легенды — ему место рядом с легендой.
- Оговорка VLAN («ВНИМАНИЕ: …») — в консоли выделена, на экране проверить
  заметность после дизайн-прохода.

### Библиотека `/presets`
- Пояснение «пресет рождается из измерения» — философия продукта серой строкой.

### Журнал `/runs`
- `Usage` (строка «Журнал: N прогонов, M сэмплов, X МБ (свободно…) · путь») —
  четыре факта и путь в одну строку; путь обрезается. Числа — чипами, путь —
  копируемым моноширинным блоком (как в настройках).
- `RetentionNotice` («Сырые сэмплы удалены политикой…») — оговорка честности,
  сливается с рядами.

### Внешние пробы `/internet/probes`
- `Note` («Шаги измеряют пересекающиеся отрезки… не складываются») — ключевая
  методическая оговорка мелким серым под шагами. Карточка «почему так».
- `Conclusion` («Итог: всё в норме» / «упали все цели…») — вердикт обычным
  текстом; вердиктам — марка и цвет уровня (словарь VerdictWording уже есть).

### Инспекторы `/internet/inspect`
- **Весь вывод — двухколоночная простыня** «категория / имя / значение» без
  группировки: system-факты, записи резолверов, согласованность и DNSSEC слиты
  в один поток (виден обрыв заголовка «…о установлено» на скриншоте осмотра).
  Просятся секции с подзаголовками по категориям фактов; предупреждения
  («резолверы разошлись») — уже оранжевым, но тонут в потоке.

### Локальные тесты и Скорость `/local/tests`, `/internet/speed`
- `Note` под заголовком (про агента и M-Lab) — инструкция серой строкой.
- `Status` прогонщика («Завершено. Отправлено… В журнале: id») — вердикт, числа
  и ссылка на журнал в одной строке; id прогона должен быть ссылкой/кнопкой
  «открыть в журнале».
- «О точности» и прочие факты-оговорки в таблице фактов — уже неплохо
  (жёлтым при IsWarning), но методические факты («шкала Waveform — соглашение
  сообщества») визуально не отличаются от измеренных.

### Мониторы `/monitors`
- Строка про «полную власть над расписанием — у storm monitors add» — совет
  с командой; командам — моноширинный чип, копируемый.
- SLA-текст («доступность 100 % от наблюдавшегося… покрытие 0 % — доверять
  нельзя») — лучший честный текст продукта, набран как все: дискредитация
  доверия к числу должна быть визуально громче самого числа.

### Расписание `/schedule`
- Объяснение окон обслуживания («считать простоем — завышать…») — методика
  серой строкой.

### Отчёты `/reports`
- «Продукт заключение не составляет…» — принципиальная позиция; и подсказка
  «эталоны снимаются из консоли: storm baseline capture» — команда в тексте.

### Алерты `/alerts`
- «Настраиваются из консоли: storm alerts set…» — инструкция с командой.

### Настройки `/settings`
- **Самая плотная страница по простыням**: у каждой секции 1–3 абзаца
  FontSize 10 Opacity 0.5 («Порог 50 мс, разумный в офисе…», «Продукт узнаёт
  сеть, но не переключает…», SecretsNote, SnmpNote, UpdateNote, LicenceNote,
  заметки агентов). Тексты отличные — и именно их «плашмя» больше всего.
  Направление: короткий тезис виден всегда, развёртка — по ⓘ/спойлеру;
  команды консоли — моноширинными чипами.

### Разработка `/dev`
- Карточки возможностей — эталон формы (точка-статус, заголовок, объяснение,
  оранжевое «что сделать»). Использовать как образец для остальных.

## Словарь форм для дизайн-прохода (предложение)

| Род текста | Форма |
|------------|-------|
| Методика, «почему так» | карточка с ⓘ, заголовок-тезис + развёртка |
| Оговорка честности | жёлтая строка с ! (как HowToEnable) |
| Инструкция с командой | текст + моноширинный копируемый чип команды |
| Условия измерения | бейджи-чипы в шапке |
| Статистика | плитки-счётчики (образец — низ Задержки) |
| Легенда | пары «знак → значение», не предложение |
| Статус операции | своё место + иконка состояния |
