## 1. Понимание задачи

### 1.1 Что мы строим

Настольная инженерная станция диагностики сетей: единый инструмент, который заменяет
россыпь утилит (`ping`, `tracert`, `nmap`, `iperf3`, `mtr`, speedtest, SNMP-браузеры)
связной системой с памятью, расписанием и отчётностью.

Ключевое отличие от набора утилит — **три сквозные способности**:

1. **Память.** Любое измерение сохраняется во временной ряд. «Сеть тормозит» превращается
   из ощущения в график с baseline.
2. **Повторяемость.** Любой тест сохраняется как пресет и ставится на расписание.
3. **Артефакт.** Любой набор результатов превращается в PDF-отчёт со ссылкой на методику,
   который можно предъявить провайдеру, заказчику или руководству.

### 1.2 Кто пользователь

| Роль | Задача | Что критично |
|------|--------|--------------|
| Сетевой инженер / админ | Диагностика инцидента «здесь и сейчас» | Скорость запуска, глубина данных, точность |
| Эникей / IT-специалист | Регулярный контроль офисной сети | Автоматика, понятные вердикты, алерты |
| Интегратор / подрядчик | Приёмка сети, доказательство SLA | Отчёты PDF, baseline vs current |
| Техподдержка провайдера | Разбор жалобы абонента | Внешние тесты, трассировки, история |

Первичный профиль — **сетевой инженер**. Дефолты настраиваем под него; «понятные вердикты»
добавляем поверх сырых данных, а не вместо них.

### 1.3 Открытый исходный код

Продукт распространяется под OSI-одобренной лицензией. Следствия, влияющие на архитектуру:

| Следствие | Что это даёт / требует |
|-----------|------------------------|
| QuestPDF Community покрывает open-source проекты | ✅ Лицензионный риск отчётов снят |
| SignPath Foundation даёт **бесплатную OV-подпись** проектам с OSI-лицензией | ✅ Решает проблему SmartScreen без затрат. Требует: публичный репозиторий, воспроизводимая сборка из него, активная поддержка |
| Публикация издателя — «SignPath Foundation», не наше имя | ⚠️ Принимается как цена бесплатной подписи |
| LGPL-зависимости (SharpPcap) перестают быть проблемой совместимости | ✅ Но техническое ограничение на trimming остаётся |
| Требуется выбрать конкретную лицензию | ⬜ Решение Этапа 4. Рекомендация: **MIT** — совместима с LGPL-плагином и с условиями SignPath |
| Код виден всем, включая службы ИБ заказчиков | ✅ Сильный аргумент против подозрений «это сканер портов» |

### 1.4 Границы (что НЕ делаем)

- Не делаем полноценный packet analyzer (это Wireshark).
- Не делаем эксплуатацию уязвимостей и брутфорс — только инвентаризация и диагностика.
- Не делаем NMS уровня Zabbix с агентами на каждом узле.
- Не делаем нагрузочное тестирование приложений (это k6/JMeter).
- Не делаем управление конфигурацией устройств (только чтение).

### 1.5 Этика и легальность

Функции обнаружения применимы **только к сетям, которыми пользователь владеет
или администрирует**. Закладываем:

- подтверждение диапазона сканирования при первом запуске в новой подсети;
- rate-limit по умолчанию;
- отсутствие эксплойт-модулей;
- журнал всех активных действий.

## 2. Доменная модель

```
Target ──┐
         ├──> Preset ──> Suite ──> Schedule ──> Run ──> Result ──> Report
Probe ───┘                                        │
                                                  └──> Alert
```

| Сущность | Определение |
|----------|-------------|
| **Target** | Цель: IP, hostname, URL, подсеть, устройство из топологии, «шлюз», «внешний IP» |
| **Probe** | Атомарный тип измерения: ICMP-echo, TCP-connect, HTTP-GET, DNS-query, SNMP-get, UDP-jitter, throughput… |
| **Preset** | Probe + Target(ы) + параметры + пороги вердикта. Именованный, версионируемый, CRUD |
| **Suite** | Композиция пресетов (последовательно / параллельно, с зависимостями) |
| **Schedule** | Когда выполнять: разово, интервал, cron, окно обслуживания |
| **Run** | Факт выполнения: время, **условия измерения**, статус, ссылки на результаты |
| **Result** | Временной ряд + агрегаты + **метаданные методики** + вердикт |
| **Alert** | Событие перехода порога + канал доставки |
| **Report** | Шаблон + выборка прогонов → PDF |

**Сквозной UX-принцип:** из любого места работают три действия — *«Сохранить как пресет»*,
*«Поставить на расписание»*, *«Добавить в отчёт»*.

### 2.1 Инвентарь и топология

```
Discovery Scan ──> Device (Node) ──> Interface ──> Link ──> Topology (граф)
                        │
                        └──> Evidence (ARP, SendARP, SNMP, LLDP, FDB, mDNS, ping, OUI, traceroute, ручная правка)
```

Узлы и связи **не хранятся как правда** — они вычисляются из набора **Evidence**, каждое
из которых несёт источник, время и уровень достоверности. Ручная правка оператора — тоже
Evidence, с наивысшим приоритетом и флагом `pinned`.

**Исследование подтвердило необходимость этой модели** (`R-05`). Реальность такова:

- LLDP не реализован в дешёвых свитчах;
- неуправляемый свитч или хаб между инструментом и управляемым свитчем **ломает топологию** —
  инструмент покажет неверную связность, будучи уверен в обратном;
- ПК, принтеры и IoT себя не анонсируют вообще.

**Отсюда жёсткое требование: ложная точность недопустима.** Связь, выведенная эвристикой,
обязана визуально отличаться от связи, подтверждённой LLDP. Пользователь должен видеть,
насколько мы уверены, и на основании чего.

## 3. Градация функциональности по зависимостям (новое в ред. 2)

Ключевая структурная находка исследования: функционал распадается на три уровня
по тому, что нужно установить и получить.

### Уровень 0 — Ядро. Ничего не требует

Работает сразу после установки, **без прав администратора, без драйверов, без учётных данных.**
Подтверждено экспериментами (`R-01`, `R-02`, `R-10`).

| Возможность | Механизм |
|-------------|----------|
| ICMP-пробы, непрерывный мониторинг | `IcmpSendEcho2`, опционально raw-сокеты |
| Traceroute / MTR | `IcmpSendEcho2` с TTL |
| PMTU, тест jumbo frames | DF-бит |
| **Инвентаризация подсети с MAC-адресами** | ping-sweep + `SendARP` + `GetIpNetTable` |
| Вендор устройства | офлайн-база OUI |
| Имена устройств | reverse DNS, NetBIOS, mDNS, SSDP, WS-Discovery |
| TCP/UDP/HTTP/DNS/TLS пробы | сокеты, DnsClient.NET |
| Throughput, jitter, PDV, MOS | `storm-agent` на второй точке или iperf3-сервер |
| Bufferbloat, speedtest | NDT7 / агент |
| Топология L3 | traceroute, таблица маршрутизации, ARP |
| Пресеты, расписание, отчёты, алерты | целиком |

**Это ~80% ценности продукта.** Первый запуск обязан работать на этом уровне.

### Уровень 1 — «+SNMP». Требует учётных данных оборудования

| Возможность | Что даёт |
|-------------|----------|
| Точная L2-топология | LLDP-MIB через SNMP: кто с кем и каким портом соединён |
| Привязка устройства к порту свитча | BRIDGE-MIB `dot1dTpFdbTable` |
| Счётчики ошибок интерфейсов | CRC, discards, duplex mismatch — находит «умирающий патч-корд» |
| Реальная утилизация портов | счётчики байтов без создания нагрузки |
| Инвентарь оборудования | sysDescr, ifTable, скорости портов |

Деградация при отсутствии: топология строится эвристиками, достоверность связей понижается явно.

### Уровень 2 — «+плагин захвата». Требует установленного Npcap

| Возможность | Почему только так |
|-------------|-------------------|
| Приём LLDP/CDP-кадров напрямую | нужен L2-захват |
| Пассивный анализ трафика | — |
| Детект rogue DHCP по broadcast | активный DHCP-запрос покрывает лишь часть случаев |
| Пассивный OS-fingerprint | — |

**Правовое решение (`R-02`): Npcap не распространяется вместе с продуктом ни при каких условиях.**
Его лицензия (NPSL) основана на GPLv2, но **не является open-source** и запрещает
распространение без отдельного разрешения. У Wireshark для этого есть именное исключение,
у нас его нет.

Механика: продукт **детектирует уже установленный Npcap**. Если его нет — показывает,
какие функции недоступны, и даёт ссылку на официальный сайт. Установку выполняет пользователь.

### Правило градации

Каждый уровень деградирует **явно и объяснимо**. Недоступная функция не прячется —
она показывается неактивной с пояснением «что это даёт» и «что нужно включить».
Это прямое следствие UX-принципа §9.4.6.

## 6. Сквозная функциональность

| # | Возможность |

| C-01 | CRUD пресетов: создать, клонировать, редактировать, удалить, тегировать, искать |

| C-03 | Версионирование пресета — изменение параметров не ломает интерпретацию старых результатов |
| C-04 | Suite: композиция «последовательно / параллельно», условия и зависимости |
| C-05 | Планировщик: разово, интервал, cron, окна обслуживания |
| C-06 | Политика misfire: пропустить / выполнить при старте (сон, выключение, перезагрузка) |
| C-07 | История запусков с фильтрами, drill-down до сырых измерений |
| C-08 | **PDF-отчёты**: шаблоны, графики, таблицы, топология, выводы |
| **C-08a** | **Каждое измерение в отчёте сопровождается указанием методики** (RFC 3550, RFC 6349, G.107, Y.1564) |
| **C-08b** | **Секция «Условия измерения»**: интерфейс, его тип, версия продукта, бэкенд, калибровочный базис |
| C-09 | Baseline: зафиксировать эталон, сравнивать «было / стало» |
| C-10 | Экспорт CSV / JSON / PNG |
| C-11 | Алерты: пороги, гистерезис, каналы (трей, звук, e-mail, webhook) |
| C-12 | Профили сетевого окружения: «офис», «дом», «объект заказчика» |

### 6.1 Измерение скорости между точками

Решение оператора: **основа — собственный агент `storm-agent`.** Исследование добавило:

- raw-сокеты и UDP доступны **без прав администратора** → агент не требует admin
  (кроме установки как службы);
- собственный джиттер стека **0.008 мс** → точности хватает для честных throughput/jitter/PDV;
- темповка пакетов требует **гибридного spin-wait** — `Thread.Sleep` непригоден,
  `timeBeginPeriod` не помогает. Цена: генератор занимает ядро CPU на время теста.

Дополнительно: совместимость **как клиент** с существующими `iperf3 -s` (BSD-лицензия
позволяет, но бинарь не бандлим) и чтение SNMP-счётчиков как неразрушающая альтернатива.

### 8.2 Принципиальные решения

**Из редакции 1 (подтверждены):**

1. **Probe — плагин.** Единый интерфейс `IProbe`: декларация параметров, валидация,
   выполнение с отменой, поток измерений, агрегация, вердикт. UI строит форму
   по декларации — новая проба не требует правки UI.
2. **Ядро без GUI.** Ни одна строка домена и слоя приложения не ссылается на UI.
3. **Результат = поток + агрегат.** Поток сырых сэмплов для живого графика, агрегация
   для истории и отчёта.
4. **Вердикт отделён от измерения.** Пороги — конфигурация пресета. Прогон можно
   переоценить с другими порогами.
5. **Топология = граф + свидетельства.** Пересчёт — детерминированная функция от Evidence.
6. **Планировщик persistent.** Расписания переживают перезапуск; misfire-политика явная.
7. **Отмена везде.** Любая долгая операция прерываема.

**Новые в редакции 2:**

8. **Время меряем только своим таймером.** Значения RTT/latency из системных API
   (`PingReply.RoundtripTime` и аналоги) **не используются никогда** — они дают целые
   миллисекунды и превращают LAN-измерения в мусор. Нарушение = блокер ревью.
9. **Ноль аллокаций в горячем пути измерений.** Переиспользуемые буферы, никакого LINQ
   и boxing внутри цикла проб. Только при этом условии GC не влияет на результат
   (проверено: 0 пауз за 300 замеров).
10. **Внешние библиотеки — за собственными интерфейсами.** `IReportRenderer`,
    `IChartRenderer`, `IGeoProvider`, `ISpeedTestBackend`, `ICaptureProvider`.
    Замена реализации не должна затрагивать домен.
11. **Опциональные зависимости — отдельные плагины.** Ядро о них не знает и работает
    без них. Драйвер захвата никогда не входит в дистрибутив.
12. **Каждое измерение несёт метаданные условий:** интерфейс и его тип, калибровочный
    базис, версия продукта, использованный бэкенд, ссылка на методику. Без этого
    результат несопоставим между запусками и бесполезен в отчёте.

### 8.3 Технологический стек

Зафиксирован в [ADR-0001](adr/ADR-0001-technology-stack.md): .NET 8 + Avalonia 11,
AvaloniaGraphControl (MSAGL) + Nodify.Avalonia, ScottPlot, QuestPDF, SharpSnmpLib,
DnsClient.NET, Quartz.NET, SQLite, DB-IP Lite, Velopack.

### 9.4 Ключевые потоки

**Поток 1 — «Первый запуск» (time-to-value < 60 с)**
```
Приветствие → детект интерфейсов и подсети → предупреждение, если адаптер виртуальный
→ подтверждение диапазона сканирования → обнаружение (замерено: /24 за 1.55 с)
→ карта сети + список устройств → предложение «создать базовый мониторинг»
```

**Поток 2 — «Инцидент: сеть тормозит»**
```
Дашборд (красный монитор) → drill-down в график
→ «Запустить диагностику» (ping шлюза + MTR до внешнего узла + bufferbloat)
→ вердикт с указанием проблемного участка → «Отчёт для провайдера» → PDF с методикой
```

**Поток 3 — «Приёмка объекта»**
```
Профиль «Объект X» → обнаружение → правка топологии → Suite «Приёмка»
→ прогон → отчёт «Акт тестирования» → зафиксировать baseline
```

**Поток 4 — «Регулярный контроль»**
```
Любой тест → «Сохранить как пресет» → «Поставить на расписание» → алерт по порогу
→ периодический PDF
```

### 9.5 UX-принципы

1. **Троеточие возможностей.** На любом экране результата: «в пресет», «в расписание», «в отчёт».
2. **Сырое и понятное вместе.** Вердикт человеческим языком *и* разворачиваемые сырые цифры.
3. **Объяснимость.** Рядом с вердиктом — какой порог и какая метрика его дали.
4. **Прогресс, а не спиннер.** Долгие операции показывают найденное по ходу.
5. **Ничего не теряется.** Прерванный тест сохраняет то, что успел измерить.
6. **Недоступное не прячется.** Функция вне текущего уровня показывается неактивной
   с пояснением «что даёт» и «как включить».
7. **Честность о неопределённости.** Достоверность связей топологии и условия измерения
   отображаются всегда. Ложная точность хуже отсутствия данных.
8. **Безопасные дефолты.** Агрессивные режимы включаются осознанно.
