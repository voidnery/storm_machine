## 1. Слои и направление зависимостей

```
   Presentation          App (Avalonia)        Cli            Agent
                                │                │               │
                                └────────┬───────┘               │
                                         ▼                       │
   Application              StormMachine.Application ◄───────────┘
                                         │
                                         ▼
   Domain                    StormMachine.Domain
                                         ▲
                                         │
   Infrastructure     Probes · Discovery · Platform · Storage
                      Reporting · Scheduling · Protocol
                                         ▲
                                         │
   Plugins                  Capture.Npcap (опционально)
```

**Правило:** зависимости направлены внутрь. `Domain` не знает никого. Инфраструктура
реализует интерфейсы, объявленные в `Application`, и подключается через DI.

## 3. Правила, проверяемые тестами

`tests/StormMachine.ArchTests` содержит правила, нарушение которых **роняет сборку**:

| № | Правило | Зачем |
|---|---------|-------|
| 1 | `Domain` не ссылается ни на один проект и ни на один NuGet-пакет | Чистота модели |
| 2 | `Application` ссылается только на `Domain`; из пакетов — лишь `*.Abstractions` | Инверсия зависимостей |
| 3 | `App` и `Cli` не ссылаются на инфраструктуру напрямую | Ядро не прирастает к интерфейсу |
| 4 | SharpPcap и PacketDotNet — только в `plugins/` | Изоляция LGPL + работоспособность trimming |
| 5 | Avalonia — только в `StormMachine.App` | Ядро не знает о существовании UI |
| 6 | `PingReply.RoundtripTime` не встречается в коде `src/` (комментарии не в счёт) | Принцип 8.2.8: API даёт целые миллисекунды |
| 7 | Типы QuestPDF не выходят за пределы `Reporting` | Заменяемость PDF-движка |

Правило 6 проверяется по коду с вырезанными комментариями — упоминание запрещённого API
в пояснении, почему он запрещён, нарушением не является. Само вырезание покрыто
отдельными тестами (`CommentStrippingTests`): иначе правило могло бы незаметно
перестать что-либо ловить, продолжая гореть зелёным.

## 4. Ключевые абстракции

### `IProbe` — проба как плагин

Единый интерфейс для всех измерений. Объявляет свои параметры декларативно —
UI строит форму по декларации, поэтому новая проба **не требует правки интерфейса**.

Контракт: описание параметров → валидация → выполнение с отменой → поток сэмплов →
агрегация → вердикт.

### `Result` — поток и агрегат

Каждая проба отдаёт **поток сырых сэмплов** (для живого графика) и **агрегацию**
(для истории и отчёта). Общая часть хранится в колонках, специфика пробы — в JSON-поле.

### `MeasurementContext` — условия измерения

Сопровождает каждый результат: сетевой интерфейс и **его тип** (физический /
виртуальный / VPN / Wi-Fi), калибровочный базис, версия продукта, использованный бэкенд,
ссылка на методику (RFC). Без этого результаты несопоставимы между запусками
и бесполезны в отчёте.

### `Evidence` — свидетельство о топологии

Узлы и связи не хранятся как правда — они **вычисляются** из набора свидетельств
(ARP, `SendARP`, SNMP, LLDP, FDB, mDNS, ping, OUI, traceroute, ручная правка).
Каждое несёт источник, время и уровень достоверности. Правка оператора — тоже
свидетельство, с наивысшим приоритетом и флагом `pinned`.

Пересчёт графа — **детерминированная функция** от набора свидетельств, а не мутация
состояния. Отсюда следует, что повторное сканирование не может затереть правку человека.

## 5. Горячий путь измерений

Отдельный режим кода со своими правилами:

- **Только собственный таймер** высокого разрешения. Значения RTT из системных API
  не используются никогда.
- **Ноль аллокаций**: переиспользуемые буферы, никакого LINQ и boxing внутри цикла.
  Проверяется тестом по дельте `GC.GetAllocatedBytesForCurrentThread()`.
- **Калибровка**: базис накладных расходов измеряется на loopback при старте и вычитается.
- **Темповка пакетов** — гибридный spin-wait в выделенном потоке. `Thread.Sleep`
  непригоден (спит вдвое дольше), `timeBeginPeriod` не помогает.

## 6. Границы, подготовленные к server-варианту

`Application` не знает, кто его вызывает: GUI, CLI или (в будущем) HTTP-сервер.
Контракт между презентацией и приложением **сериализуем** — чтобы завтра стать сетевым.

`StormMachine.Cli` существует в том числе как доказательство этого свойства:
если консоль работает, значит ядро действительно не зависит от интерфейса.
